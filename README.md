# Контроль обучения персонала

Веб-приложение для учёта обязательного обучения работников вместо Excel-таблицы:
кого, чему и когда обучили, у кого подходит срок, где просрочка, и управленческий дашборд.
Без ИИ: все расчёты по явным правилам.

## Что умеет

| Раздел | Назначение |
|---|---|
| Дашборд | доля обучений «в норме», просрочено, не пройдено, истекает; потребность в обучении на 12 месяцев; проблемные подразделения и курсы; переход к списку людей по клику |
| Контроль сроков | каждая пара «работник × обязательный курс» со статусом на любую дату; фильтры; выгрузка в Excel; выбор людей и групповое внесение обучения |
| Матрица обучения | работники × курсы, цветом статус, выгрузка в Excel с заливкой |
| План обучения | сколько человек и по какому курсу нужно обучить: срочно и по месяцам; из ячейки плана сразу во внесение записи |
| Внести обучение | одна запись на группу: курс, дата, протокол, организация; срок действия считается по периодичности курса, можно задать вручную |
| Работники | список и карточка: обязательные курсы со статусами, вся история, индивидуальные требования, перевод, увольнение |
| Курсы и требования | справочник курсов (периодичность, основание, часы) и обязательные курсы по должностям |
| Оргструктура | площадки, подразделения, должности |
| Импорт и выгрузка | загрузка работников и истории обучения из .xlsx (шаблоны в приложении), выгрузка реестра и истории, резервная копия |
| Журнал изменений | кто, когда и что изменил |
| Администрирование | пользователи, роли, зоны ответственности, порог «истекает» |

### Как считается статус

* Обязательные курсы работника = курсы его должности + индивидуальные требования.
* Берётся последняя запись обучения по курсу с датой не позже выбранной даты.
* «Действует до» = дата обучения + периодичность курса (или дата, указанная в записи вручную). Курс без периодичности считается однократным.
* Статусы: **Действует**, **Истекает** (до окончания срока осталось не больше N дней, N в настройках, по умолчанию 30), **Просрочено**, **Не пройдено** (записи нет).
* «В норме» = Действует + Истекает. «Работник с нарушением» = хотя бы одно обучение просрочено или не пройдено.
* Уволенные (с даты увольнения) и ещё не вышедшие на работу в расчёт не попадают.

### Роли

| Роль | Права |
|---|---|
| Администратор | всё, включая пользователей, настройки, площадки |
| Ответственный за обучение | вносит данные по своим площадкам; если площадки не указаны, по всему предприятию и тогда же может менять курсы и требования |
| Руководитель подразделения | только просмотр своих подразделений (или площадок) |
| Наблюдатель | просмотр всего предприятия без изменений |

## Быстрый запуск (пробный, на своём компьютере)

Нужен Node.js 18 или новее.

```bash
npm install
SEED_DEMO=1 ADMIN_PASSWORD=придумайте-пароль npm start
```

Откройте http://localhost:3000, логин `admin`. Данные хранятся в файле `data/training.db` (SQLite).
`SEED_DEMO=1` при пустой базе загружает вымышленное предприятие (около 800 работников) для пробы.

В Windows (PowerShell):
```powershell
$env:SEED_DEMO="1"; $env:ADMIN_PASSWORD="придумайте-пароль"; npm start
```

## Установка на сервер заказчика (Docker + PostgreSQL)

```bash
cp .env.example .env      # заполните POSTGRES_PASSWORD, JWT_SECRET, ADMIN_PASSWORD; SEED_DEMO=0
docker compose up -d --build
```

Приложение откроется на порту `APP_PORT` (по умолчанию 3000). Для доступа по HTTPS поставьте перед ним обратный прокси
(nginx или корпоративный) и включите `COOKIE_SECURE=1`, `TRUST_PROXY=1`.

Без Docker: установите Node.js, задайте переменные из `.env.example` (в том числе `DATABASE_URL=postgres://...`)
и запустите `npm ci --omit=dev && npm start` как службу (systemd, pm2 или служба Windows).

Приложение не обращается в интернет: библиотека Excel отдаётся с того же сервера. Подходит для закрытого контура.

## Размещение на Hostinger VPS (Docker + SQLite)

В репозитории есть отдельная конфигурация для VPS: приложение хранит SQLite в `data/training.db`, а Caddy автоматически получает HTTPS-сертификат для домена.

1. На VPS установите Docker Engine и Docker Compose plugin, затем клонируйте репозиторий.
2. Создайте `.env` из `.env.hostinger.example`. Укажите домен, задайте `ADMIN_PASSWORD` и создайте длинный случайный `JWT_SECRET` (например, `openssl rand -hex 32`). Не публикуйте `.env`.
3. До первого запуска подготовьте постоянную папку данных: `mkdir -p data && sudo chown 1000:1000 data`.
4. Если нужно сохранить существующие рабочие данные, сначала перенесите актуальный файл SQLite в `data/training.db`. Не используйте копию из GitHub: база намеренно исключена из репозитория. Для новой пустой базы файл создастся автоматически.
5. Направьте A-запись `uchcontrol.sdiagnost.ru` на IPv4-адрес VPS, откройте входящие порты TCP 80 и 443 в брандмауэре и запустите `docker compose -f docker-compose.hostinger.yml up -d --build`.
6. Проверьте `docker compose -f docker-compose.hostinger.yml ps` и `docker compose -f docker-compose.hostinger.yml logs -f app caddy`.

`data/` подключена как постоянная папка хоста, поэтому пересборка контейнера не удаляет SQLite. Настройте регулярные резервные копии этой папки. Не переключайте домен с текущего сервера до проверки входа и данных на VPS.

### Резервное копирование

* PostgreSQL: штатный `pg_dump` по расписанию.
* SQLite: копия файла `data/training.db` (лучше при остановленном приложении).
* Дополнительно: «Импорт и выгрузка» → «Резервная копия (JSON)».

## Перенос данных из текущей Excel-таблицы

1. «Курсы и требования» → завести курсы с периодичностью и кодами.
2. Там же, вкладка «Требования по должностям»: отметить обязательные курсы.
3. «Импорт и выгрузка» → импорт работников (шаблон в приложении).
4. Импорт истории обучения: достаточно последней записи по каждому курсу у каждого работника.

Заголовки колонок распознаются по смыслу («Таб. №», «Табельный номер», «ФИО», «Подразделение», «Цех» и т. п.).
Перед загрузкой показывается предпросмотр, после загрузки отчёт об ошибках по номерам строк.

## Устройство

```
shared/core.js        расчёт статусов, дашборда, плана (чистые функции)
shared/service.js     методы API, права доступа, проверки, журнал изменений
shared/seed.js        генератор демо-данных
shared/memory-repo.js хранилище в памяти (демо и тесты)
server/index.js       Express: вход, сессии (JWT в httpOnly cookie), POST /api/call/<метод>
server/db.js          SQLite / PostgreSQL через knex, схема создаётся автоматически
public/               интерфейс без сборки (HTML + JS), api-http.js для сервера, api-demo.js для демо
scripts/build-demo.js сборка автономной демо-версии в один HTML-файл (dist/demo.html)
test/smoke.js         проверка расчётов и прав: npm test
```

Один и тот же код расчётов и прав работает и в демо (в браузере), и на сервере.

### Ограничения текущей версии (честно)

* Сервер держит копию данных в памяти и считает статусы там: это быстро для десятков тысяч работников
  (на 800 работниках и 10 тыс. записей дашборд считается за десятки миллисекунд), но приложение должно
  работать **в одном экземпляре**. Для кластера расчёты нужно перенести в SQL.
* Нет уведомлений по почте (нужны данные SMTP заказчика), нет входа через Active Directory / LDAP.
* Нет вложений (сканы протоколов и удостоверений).
* Нет истории «как было на дату» для оргструктуры: при расчёте на прошлую дату используются текущие должность и подразделение работника.
* Вариант с PostgreSQL проверен меньше, чем с SQLite: перед вводом в эксплуатацию прогоните пробный запуск на стенде заказчика.
* Периодичность курсов в демо-данных примерная. Для работы задайте её по нормативным документам предприятия.

## Что можно добавить следующим этапом

* Рассылка напоминаний руководителям и ответственным (за 30 дней, при просрочке).
* Вход через доменную учётную запись (LDAP / AD).
* Загрузка сканов протоколов и удостоверений.
* Формирование протокола и приказа на обучение группы по шаблону.
* Снимки состояния по месяцам для графика динамики.
* Интеграция с 1С:ЗУП для автоматической загрузки работников и переводов.
